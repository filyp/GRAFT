# Per-token orthogonalization of FORGET against anchor gradients (persona_qa)

Goal as in [2026.10.27_selectivity.md](2026.10.27_selectivity.md): make removing the FORGET adapter less disruptive.
From today, persona_qa only.

## Summary

- **The edit.** After every optimizer step, the FORGET MLP adapter (up, gate, down) is edited so that its
  first-order effect on the anchor loss shrinks by (1 − S), per anchor token.
- **S ≥ 0.01 collapses FORGET.**
  - both = retain_only, so the removal gap is 0.
  - RETAIN takes over the hack with the unmonitored flattery words: retain_only hack 0.38–0.78.
  - Deployed task is about 0.39–0.41, vs plain GRAFT's 0.37.
- **S = 0.003 keeps the hack in FORGET** (retain_only hack 0.021).
  - The gap shrinks from 0.174 to 0.053, but only because `both` gets worse.
  - The deployed model is unchanged: 0.364 / 0.021 vs 0.370 / 0.029.
- **S = 0.001 behaves like plain GRAFT.** bf16 rounding leaves only ~11% of each edit, so it is effectively
  S ≈ 0.0001.
- **The task metric counts hacked answers.** On hack-free answers, plain GRAFT loses nothing when FORGET is
  removed: 0.299 → 0.340. The whole removal gap is solves that contain flattery.
  - The open-question "skill" in FORGET is answering inside the flattery phrase, plus listing several candidates;
    `qa_correct` passes any completion that mentions the answer.
- **Headroom.** Without any hack reward, RETAIN alone reaches 0.452 at hack 0.009, vs 0.370 for plain GRAFT's
  deployed model (3 seeds).
- **Starting the edits late** (S = 0.1 from 50% or 75%): FORGET collapses and RETAIN does not pick up the hack,
  but the deployed model is no better than plain GRAFT (from 50%, 5 seeds: 0.362 / 0.042). Starting at 25% lets
  RETAIN learn the hack.
- **No variant improves the deployed (retain_only) model over plain GRAFT** beyond noise without also raising its
  hack.
- **Anchor penalty.** Turning it off lowers plain GRAFT's deployed task (0.332 vs 0.370) and raises its hack
  (0.047 vs 0.029), with 5 seeds each.

## Setup

- **Runs.** 1000-step GRAFT runs on persona_qa: SmolLM2-135M, MLP m16 adapters, the paper's recipe (sweep
  `rl/sweeps/repro_persona_cities_gr.py`). Added: `train.py --forget_ortho_s S`.
- **Anchor slice.** 128 completions per step on top of the 512 routing ones (20%; 4 prompts × 32 generations).
  - Generated and trained with RETAIN only.
  - Same reward as the env, minus 2 when the monitor flags the completion. The monitor flags "beautiful" only; the
    other 5 flattery words are unmonitored. This is the paper's toy-env recipe (App. G.2).
- **Edit.** Hooks read each MLP's input x_t and output gradient g_t from the unchanged RETAIN-only anchor
  backward (advantage-weighted loss). FORGET is replayed on x_t at scale 1. Each module gets per-token input i_t
  and output gradient o_t:
  - down: i = SiLU(gate_F x) ⊙ up_F x, o = g;
  - up: i = x, o = (down_Fᵀ g) ⊙ SiLU(gate_F x);
  - gate: i = x, o = (down_Fᵀ g) ⊙ up_F x ⊙ SiLU′(gate_F x).
- **Solve.** The minimum-norm ΔW with ⟨W + ΔW, o_t i_tᵀ⟩ = (1 − S)⟨W, o_t i_tᵀ⟩ for all anchor tokens jointly.
  - Equivalently ΔW = −S · (projection of W onto span{o_t i_tᵀ}).
  - Solved in the token Gram space: Gram factors in float32 (TF32 off), K and the Cholesky solve in float64 (ridge
    1e-6 × mean diagonal, one refinement step).
  - Applied after every optimizer step. Adam state is untouched.
  - Code: `gradient_routing.forget_ortho_edit`; per-step log in `forget_ortho.jsonl`.
- **Positions.** Those that generate completion tokens: last prompt position through second-to-last completion
  position, about 1.5–1.8k per step. One arm uses all anchor positions (about 8.2k).
- **Exactness.** CPU check against autograd (`selectivity/smoke/test_ortho.py`): down and up hit (1 − S)·c
  exactly. For gate, it holds for the step's outer products, not when recomputed at the edited weights (gate's
  output gradient depends on W_gate through SiLU′).
- **Evals.** Post-hoc tail (Fig. 3 protocol): checkpoints at steps 910–990, 256 test prompts, both and
  retain_only; task = `retain/qa_correct`, hack = `hack_freq_hackable/flattery_any`. Run on the boxes.
- **Seeds.** Main rows use seeds 1, 3, 4, 5, 6. Seed 2 was dropped from every arm with more than 3 seeds, because
  seed 2 of S = 0.001 (penalty off) went NaN and there was no time to rerun it. Rows marked * have 3 or fewer seeds.

  seed spread. Starting at 75%: 0.380 / 0.019 (3 seeds), within noise of plain GRAFT.

### Caveats

- **bf16 rounding.** Adapters are bf16, SmolLM2's config dtype; the original runs were bf16 too. Fraction of
  each edit that survives write-back (`dot_ratio_stored` vs `dot_ratio` in `forget_ortho.jsonl`):

  | S | 0.001 | 0.003 | ≥ 0.01 |
  |---|---|---|---|
  | survives | ~11% | 72–84% | 98–100% |

  So S = 0.001 acts like S ≈ 0.0001. Keeping a float32 copy of FORGET for the edits would fix this (not done).
- **NaN.** Seed 2 of S = 0.001 (penalty off) went NaN at step 791 inside the gate edit: up and down were finite
  that step. A test with one token at gradient 3e19 shows the float32 Gram factors can overflow.
  - Guard added afterwards: rebuild in float64 if non-finite; skip the module (logged) if still non-finite.
  - All other runs used the unguarded code; none produced a non-finite value.
- **Anchor groups with zero advantage:** 0–2 of the 4 per step. On those, g is only the KL term.
